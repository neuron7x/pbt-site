Ітерація від **21.11.2026**, репозиторій `neuron7x/pbt-site`,
[PR #34](https://github.com/neuron7x/pbt-site/pull/34).
Батьківський remote head: `e3994deda9971c92af1d52840f8140e41be11b9a`.
Перевірений main на початку роботи: `828abe1fd3daf0540cd28cd6636600331c195412`.

Зміни стосуються спостереження дочірніх процесів, приймання soak-звітів та

контракти не змінюються. Попередні результати залишаються історичними в
[SECURITY_INTEGRATION.md](SECURITY_INTEGRATION.md); цей запис їх не замінює.

## Відтворені дефекти та зміни

**Неповний перепис процесів.** Один доступний `task/*/children` міг приховати
відсутність цього інтерфейсу в іншого thread або descendant. Порожня чи
неповна множина тоді помилково виглядала повним спостереженням. Перепис
враховує всі threads і переходить до дерева `PPid` за неповного інтерфейсу.
Недоступний status процесу, який ще існує, не стає доказом нульових ресурсів;
зникнення процесу під час читання розрізняється з відсутністю спостереження.
Некоректні PID відхиляються, повторний PID не рахується двічі.

**Некоректні числа та суперечливі звіти.** Окремий
`tools/verify_soak_evidence.py` і verifier графа
`tools/meta_evidence_gate.py` перевіряють schema, числові типи, скінченність
вимірювань і невід'ємні цілі лічильники. `true`/`false` не підміняють числа,
рядок `"false"` не підтверджує crash/restart, а переповнений JSON exponent
не підтверджує кількість спроб. Дублікати JSON-ключів відхиляються, зокрема
у вкладених об'єктах. Додатково перевіряється, що додатна пам'ять дочірніх
процесів не поєднана з нульовою кількістю дітей у тому самому sample.

Обидва verifier окремо звіряють лічильники чинного `SyntheticCRM`:

- сума HTTP statuses дорівнює `total_webhook_attempts + expected_crash_aborts`;
- кількість `400` дорівнює очікуваним перерваним crash-запитам, коли
  invalid payload/HMAC та unexpected abort counters дорівнюють нулю;
- кількість `200` не менша за число прийнятих заявок. Вона може бути більшою:
  запізніла успішна відповідь здатна спричинити повтор доставки.

Ці умови перевіряють узгодженість виміряного звіту; самі собою вони не
автентифікують автора звіту чи provider artifacts.

**Формат результату Node.** На Node 24.22.3 успішний запуск міг мати інший
типовий reporter, тоді як Python-wrapper очікував TAP-рядок `# fail 0`.
Wrapper явно задає `--test-reporter=tap`. Формули, тарифи й property cases
калькулятора збережено; помилка property assertion і далі провалює wrapper.

**Оракул p99.** Чинний `M-ADV-04-p99-limit` зберігає ID, mutation anchor
та oracle. Позитивний звіт у тесті доповнений до повного: після вилучення
ліміту mutant більше не гине через відсутнє поле, а помилково приймає
надлімітний звіт. Oracle фіксує саме `DID NOT RAISE` і вбиває mutant.

ітерацією не підтверджені. Перепис `/proc` лишається дискретним
спостереженням, а не безперервним піком пам'яті чи cgroup-вимірюванням.

## CI та інтеграція

На батьківському remote head повторно прочитано всі **11 jobs шести
workflows**: `failure`, `runner_id=0`, `runner_name=""`, `steps=[]`.
Quality workflow не мав pending deployments. Конкретна причина відмови
платформи лишається невстановленою; це не результат виконання тестів.
Діагностика та актуальні provider-посилання зібрані в
[issue #35](https://github.com/neuron7x/pbt-site/issues/35).

Політика доказів визначає **п'ять** обов'язкових workflow roles для
остаточного head: quality, transport, visual, security і soak. Окремий
evidence-closure workflow перевіряє exact-main; на PR-події його source —
base SHA, а не PR head. Він не підміняє докази кандидата.

PR лишається Draft до фактичного проходження обов'язкових перевірок на
остаточному head. CI thresholds, вимога `make gate`, тривалість soak і
правило merge не послаблені. Deployment та підвищення assurance ledger
до VERIFIED не виконувалися. Зовнішні умови залишаються в
[PRODUCTION_HOLD.md](PRODUCTION_HOLD.md).
